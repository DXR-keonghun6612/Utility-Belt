# gui/editor/

편집기 — **골격**(`Editor_base`)과 **대상별 편집기**(`image/`)를 가른다.

한때 편집기는 하나였고 그 안에 라스터·픽셀·OpenCV·툴바·이력이 다 있었다. 그 편집기는 잘 돌았지만
**늘릴 수가 없었다** — 3d points 나 시퀀스를 편집하려면 도구 전환·이력·잠금·단축키·조준을 통째로 다시
짜야 했다. 그 다섯은 무엇을 편집하든 똑같은데도.

그래서 **아는 타입으로 계층을 가른다**:

| | 아는 것 | 모르는 것 |
|---|---|---|
| `Editor_base` | 도구 선언 → 툴바·단축키, undo/redo, 잠금, 조준, 포인터 디스패치 | 픽셀·좌표계·라스터·트리·store |
| `image/Image_editor` | 2D 라스터·bbox·OpenCV·커서 미리보기 | 트리·store·객체가 어디서 왔는지 |

Base 에 `numpy` 도 `cv2` 도 `Data_Ref` 도 없다. 그게 확장 가능하다는 말의 전부다 — 새 편집기는 캔버스와
도구와 스냅샷만 주면 된다.

---

## 계약 (`_base.py`)

서브클래스가 채우는 것:

- **`TOOLS`** — [`Tool`](_tool.py) 선언. 툴바 버튼도 단축키도 배타 그룹도 **이 선언에서** 만들어진다.
  버튼·단축키를 손으로 두 번 배선하면 반드시 어긋난다(툴바엔 있는데 단축키가 없는 식).
- **`_make_canvas()`** — 포인터를 **도메인 좌표**로 내는 위젯(`mouse_pressed(x, y)` …). 무슨 좌표인지는
  Base 가 모른다 — 이미지면 원본 픽셀, 3d 면 ray hit.
- **`_snapshot()`/`_restore()`** — 이력에 담을 것. **무엇을 되돌릴 수 있는지를 여기서 정한다**
  (`Image_editor` 는 라스터 + bbox 를 함께 담는다 — 픽셀만 담으면 상자 편집이 조용히 안 되돌아간다).
- **포인터 훅** — `_on_press`/`_on_move`/`_on_release`/`_on_right`. 조준·잠금 검사는 Base 가 이미 했다.

Base 가 주는 것: 세로 툴바 · 상태바 · 옵션바 · 캔버스 슬롯의 골격, `aim()`(조준 교체), `set_locked()`,
`undo`/`redo`, `picked` 시그널.

## 조준 — 도구는 살고 이력은 대상을 따른다

`aim(target)` 이 대상을 갈아끼운다. 이때 **도구 선택은 유지**하고(객체를 옮겨 다니며 계속 칠하는 게
라벨링이다 — 옮길 때마다 붓을 다시 고르게 하면 안 된다), **`target.key` 가 바뀔 때만 이력을 비운다**
(다른 라스터의 픽셀로 되돌아갈 수는 없으니까).

그래서 `Image_editor` 에선 같은 라벨맵 위에서 객체를 옮겨 다니는 동안 undo 가 산다. 다만 그 스택엔 *다른
객체를 겨눴을 때* 찍힌 칸이 섞이므로, 스냅샷은 **소유자를 함께** 들고 남의 bbox 는 안 되돌린다.

**조준이 없으면 편집도 없다** — 조용히 아무 라벨이나 찍지 않고, 왜 못 겨누는지를 상태바가 말한다.

## 편집기는 store 를 모른다

저장·객체 추가/삭제 단축키(`Ctrl+S`·`A`·`Delete`·`M`)는 **여기 없다** — 그건 store 를 알아야 하므로
[`meta_page/view/_view.py`](../meta_page/view/_view.py) 가 건다. 옛 `Stem_editor` 는 그걸 자기가 들고
store 를 직접 불러서, 다른 데서 재사용할 수가 없었다.

편집기가 아는 건 "무엇을 겨누고 있나"(`Target`)뿐이고, 무엇을 겨눌지 고르는 건 트리를 아는
[`Data_view`](../meta_page/view/_data_view.py) 다. 캔버스에서 뭔가를 클릭했을 때도 편집기는 **좌표만**
넘긴다(`picked`) — 거기 무엇이 있는지는 상위가 안다.

## 파일

| 파일 | 역할 |
|---|---|
| `_base.py` | 골격 — 툴바·상태바·옵션바·이력·잠금·조준·포인터 디스패치 (좌표계 무지) |
| `_tool.py` | 도구 선언 (`key`·`group`·아이콘·단축키) — 툴바와 단축키가 이걸 **읽어서** 만들어진다 |
| `_history.py` | undo/redo 스택 — 스냅샷의 **내용은 편집기가 정한다**(take/apply 콜백) |
| `image/_editor.py` | `Image_editor` — 조작(view/bbox/paint/erase) × 모양(brush/polygon/circle/fill) |
| `image/_overlay.py` | 편집 오버레이 — 보색 미리보기·커서 원·bbox 핸들 (합성 결과 위에 얹는다) |
| `image/_geom.py` | bbox 기하 — 핸들 위치·히트 판정 (그리는 쪽과 잡는 쪽이 **같은 정의**를 쓴다) |
| `image/_fill.py` | magic-wand 채우기 (색 유사 + LoG edge 벽) — core `log_edges` 재사용 |

## 이미지 편집은 두 축의 곱이다

조작(`paint`/`erase`) × 모양(`brush`/`polygon`/`circle`/`fill`). 그래서 "색이 비슷한 영역을 **지우기**"
(erase × fill)가 조합으로 공짜로 나온다. 한때 `fill`(magic wand)을 조작 축으로 올린 적이 있는데, 그 순간
곱이 깨져 **지울 수가 없어졌다** — 축을 잘못 고르면 기능이 조용히 사라진다.

`view`·`bbox` 는 mask 를 안 건드리는 별도 조작이라 모양을 참조하지 않는다.

## 라스터는 제자리에서 고친다

`Target.raster` 는 트리가 든 **바로 그 배열**이다 — 칠하면 그게 곧 데이터고, 캔버스는 그걸 다시 합성해
보여준다. 사본을 들고 나중에 합치면 진실이 둘이 된다. 대신 **이력이 사본을 든다**(그게 이력의 일이다).

디스크에 쓰는 건 편집기의 일이 아니다 — 편집기는 `changed` 만 내고, **명시적 저장**이 flush 한다
(취소 = 저장 없이 다시 읽기 — [`meta_page/view/README.md`](../meta_page/view/README.md)).

## 새 편집기를 더할 때 (3d points · 시퀀스)

`image/` 를 본떠 `Editor_base` 를 상속하고 위 네 가지(`TOOLS`·`_make_canvas`·스냅샷·포인터 훅)를 채운다.
**Base 를 고칠 일이 생기면 그건 신호다** — 그 요구가 정말 모든 편집기의 것인지, 아니면 특정 대상의
사정을 Base 로 밀어 올리는 중인지 먼저 묻는다.
