# model — 무거운 모델에 기대는 유닛

각 유닛의 인자·동작은 그 유닛의 docstring 에 있다. 이 문서는 **무엇이 왜 갈렸는지**만 다룬다.

```text
onnx/      onnx 파일 기반 backend — 기능별 클래스 + 교체되는 건 onnx 파일 하나
torch/     torch 기반 backend — 모델 코드에 기대는 런타임 (sam3)
detect/    정책 — 프롬프트 없이 프레임 통째 → 인스턴스
segment/   정책 — 객체 bbox 프롬프트 → 인스턴스 라벨맵
```

---

## backend / 정책 분리

- **backend** (`onnx/` · `torch/`) — 모델 고유 저수준 프리미티브만. **정책은 여기 없다** — best mask
  선택·이진화·구멍 보존 같은 판단이 들어오는 순간 backend 교체가 불가능해진다.
- **정책** (`detect/` · `segment/`) — backend 위에서 조립하는 **모델-무관** 층. 유닛이 backend 종류를
  모른다. config 의 `model:` 한 줄로 backend 를 갈아끼우고 정책은 그대로 둔다.

**backend 는 검출·분류기가 아니다** — class 를 정하지 않는다. `segment` 는 기존 객체 값을 그대로
유지하고, `detect` 는 전경만 내므로 class 를 모른다.

**영역 제거(구멍·슬릿 carve)는 여기 넣지 않는다** — backend 는 순수 분할만 하고, carve 는 downstream
유닛(edge·fill·combine)으로 **flow 에서 조합**한다. 여러 도메인을 엮는 일은 유닛이 아니라 config 의 몫이다.

## backend 는 `onnx` / `torch` 로 갈린다 — 기준은 **무엇을 들여오는가**

| | 들여오는 것 | 그래서 |
|---|---|---|
| `onnx/` | **파일** (`*.onnx` + `*_rt_cfg.yaml`) | 파일이 자기 입출력을 설명하므로 코드를 안 고치고 갈아끼운다 |
| `torch/` | **모델 코드** (`import sam3`) | 그 라이브러리가 아는 만큼만 — 대신 파일로 표현 못 하는 것(상태·프롬프트 루프)을 한다 |

`onnx/` 안은 **기능**으로 나뉜다(`segment.py` = 전경 분할). 파일 하나를 돌리는 일은 다 같아도
(`_runner.py`), 프레임을 어떤 배열로 싸서 넣고 나온 배열을 무엇으로 읽을지는 기능이 정하기 때문이다.
기능이 늘면 파일이 늘고, **같은 기능의 모델이 바뀌는 건 파일 교체라 코드가 안 는다.**

## 스펙은 파일이 소유한다 — 코드에 상수를 안 박는다

입출력의 이름·dtype·shape 는 **onnx 그래프가 진실**이다(`onnx/_spec.py`). 예전엔 `input_name="image"`
같은 기본값과 `_TOP, _LEFT = 6, 1` 같은 offset 을 코드에 베껴 적었고, 파일을 바꾸면 조용히 어긋났다.
지금은 offset 이 두 스펙 차이의 절반으로 유도된다(`Onnx_segmenter.Origin`).

## cfg 는 읽기만 한다 — 우리 필드를 얹지 않는다

`*_rt_cfg.yaml` 은 **변환 툴이 onnx 와 함께 매번 생성하는 산출물**이다. 그래서 거기에 LENS 가 쓸 값을
적어두면 **재-export 가 지운다** — 실제로 그렇게 잃었다(`layout` 을 넣었다가 재-export 한 파일이 못 쓰게
됐다). 산출물은 남의 것이니 우리 레시피를 섞지 않는다.

그래서 cfg 는 **순수 대조자**다: 같은 입출력을 한 번 더 적고 있으니 그래프와 맞대보고 어긋나면 터뜨린다
(중복은 어차피 생기니, 중복이 거짓말하는 것만 막는다). cfg 가 아예 없어도 그래프만으로 완전하다.
`precision`·`workspace_size_mb` 는 TensorRT knob 이라 onnxruntime 경로에선 보관만 한다.

**layout(NHWC/NCHW)은 묻지도 추론하지도 않는다.** `[1,600,800,3]` 과 `[1,1,588,798]` 은 둘 다 4-D 정수라
숫자만으론 구분되지 않지만, **알 필요가 없다**:

- **입력** — 우리가 넣는 배열이 틀린 배치면 `Tensor_spec.Check` 의 shape 대조가 어느 축이 다른지 짚어
  터뜨린다. 이름을 따로 물어볼 이유가 없다.
- **출력** — 이 기능의 출력은 mask 한 장(채널 1)이라 `(1,1,H,W)` 와 `(1,H,W,1)` 이 **같은 메모리 배열**
  이고, `squeeze` 하면 둘 다 `(H, W)` 로 떨어진다. 남은 축이 2-D 가 아니면 그 자체가 "mask 한 장이
  아니다" 라는 계약 위반이라 검사가 공짜로 따라온다.

layout 이 실제로 의미를 갖는 건 출력 채널이 여럿이 될 때(멀티클래스)다 — 그때는 이 기능이 아니라 새
기능이고, 거기서 정하면 된다.

## 전처리는 그래프에 있고, 후처리는 없다 — 그 비대칭이 맞다

`detection.onnx` 는 **원본 프레임을 그대로 먹는다**. flip(BGR→RGB) · NHWC→NCHW · `/255` · ImageNet
정규화 · crop 이 전부 그래프 앞단에 박혀 있어서, 호출 측은 raw BGR 을 넣기만 한다(밖에서 만지면 이중
처리다). 반대편은 비어 있다 — 마지막 `Conv` 가 낸 logits 가 그대로 나온다.

**이 비대칭은 결함이 아니라 경계다.** 전처리는 그 모델을 쓰려면 **반드시** 그렇게 해야 하는 것이라 파일에
붙어 다니는 게 맞고, 후처리(sigmoid·threshold·연결요소)는 **판단**이라 정책이 든다. 그래프에 넣으면
`threshold` 라는 GUI 손잡이가 파일 안에 굳고, 연결요소는 ONNX op 조차 없으며, 출력이 동적 shape 이 되어
고정 프로파일도 깨진다. backend 는 판단하지 않는다는 위 원칙이 여기서도 같은 답을 낸다.

`permute` 로 출력을 NHWC 로 맞추는 것도 **하지 않는다** — 출력 채널이 1이라 `[1,1,588,798]` 과
`[1,588,798,1]` 은 **같은 메모리 배열**이고(값이 하나도 안 움직인다), LENS 는 `squeeze` 로 읽으므로 어느
쪽이든 동일하게 돈다(검증됨). 얻는 건 이름의 일관성뿐이라 export 에 줄을 늘릴 이유가 없다.

## 출력이 588×798 인 이유 — resize 가 아니라 crop 을 골랐다

백본이 **patch 14** 라 입력이 14의 배수여야 하는데 원본 600×800 은 나누어떨어지지 않는다
(`600/14 = 42.86`, `800/14 = 57.14`). 둘 중 하나를 골라야 했고 **crop 을 골랐다 — resize 는 이미지의
특징을 뭉갠다.** 그래서 `42×14 = 588`, `57×14 = 798` 이고, 그 crop 은 그래프 안에 있다
(`Slice starts=[6] ends=[594]` · `starts=[1] ends=[799]` — **중앙**).

정책이 출력을 원본 canvas 중앙에 되돌려 앉히는 이유가 이것이다. 그 offset `(6, 1)` 은 코드에 박힌 상수가
아니라 **프레임과 출력의 크기 차이의 절반**으로 나오는데, 그게 그래프의 실제 `Slice` 위치와 일치한다
(모델이 중앙을 잘랐으니 중앙으로 되돌린다). dataset 이 14의 배수로 바뀌면 crop 이 사라져 offset 은 저절로
`(0, 0)` 이 된다 — 고칠 코드가 없다.

가중치(`onnx/weights/*.onnx`)는 **gitignore** 다(89MB+). cfg 는 커밋해 무엇을 넣을지 남긴다.

**GPU 전용** — CUDA provider 가 없으면 CPU 로 안 떨어지고 터진다. 성능이 소리 없이 죽는 것보다 부재를
드러내는 게 낫다.

## 비싼 인코딩은 프레임당 1회

`segment` 는 이미지 backbone 을 한 번 돌리고 객체 box 마다 가벼운 디코드만 한다(객체 수만큼 인코딩을
반복하지 않는다). 이게 `unit: frame` 인 이유다.

---

무거운 모델은 유닛이 **소유하지 않는다** — pipeline 이 스펙당 1회 빌드해 주입하고 유닛은 핸들만 든다.
모델 type→빌더는 `core/_base.py` 의 `MODEL_BUILDERS`. **type 은 기능을 고르고**, 그 기능의 어떤 모델을
쓸지는 빌더 파라미터가 정한다(`onnx_seg` 는 `onnx_file`).

> `torch/_sam3.py` 는 **상태를 든 런타임**이라 스트리밍 유닛도 자유함수도 아니다 — 이 층에 있을 것이
> 아니라는 신호. 열린 논의는 [`../../TODO.md`](../../TODO.md).
