### 묶기를 `Axis` 로 재구성하고 계산은 밖으로 (재편 이후)

정규화는 `equalize` 하나로 박혀 있고 축 연결은 `join`(곱집합)+`impute`+weld 로 박혀 있다.
갈래는 둘이다:

| 축 | 국면 | 지금 | 할 것 |
|---|---|---|---|
| **축 구성** | ① 무엇을 읽나 | `feature: radial_rle` | 당분간 하나로 제한 |
| | ② 어떻게 접나 | `folds: [signed] / [outline]` | 당분간 둘로 제한 |
| | ③ 어떻게 정규화하나 | `equalize` 하나 (자리 없음) | **선택지를 연다** |
| **축 연결** | 종합 | 곱집합 고정 | **선택지를 연다** |

#### 무엇이 밖으로 가고 무엇이 남나

판별은 *"정본·class·검수 상태 없이 호출할 수 있나"* 인데 `Dataset_Meta`·`id_map` **자체가 나가므로**
(→ 루트 [`TODO.md`](../../TODO.md)) 군집 쪽은 거의 전부 밖이다.

| 조각 | 아는 것 | 간다 |
|---|---|---|
| `cluster.py` 718줄 전부 | `(n,D)` 배열·정수 label (import 가 numpy·dataclasses·collections) | `func/format/clustering/` |
| `extract.Fold` · `RADIAL_FOLDS` | radial 의 슬롯 구조 | `func/format/radial/` — 압축은 포맷 연산 |
| `cache.py` · `template.py` | 배열 묶음·대표값 (`TO_STORAGE` 하나만 씀) | 밖 |
| `Cluster_Bucket` 의 배정·통계·서명 | 군집 결과의 영속 | 밖 |
| `class_usage`·`cleanup_hints`·`class_trust` | label × 군집 대조 | 밖 — id_map 을 따라간다 |
| **`state` · `class_src` · `propagate`** | **이 값이 어디서 왔나** | **LENS** |

**LENS 에 남는 것은 검수다** — 어떤 표본이 어느 단계인가, 그 값이 측정인가 추정인가 사람 결정인가,
그 결정을 언제 정본에 쓰나. 군집은 도구고 도구는 밖으로 간다.

#### `Axis` — 축 하나가 한 객체

축별 손잡이가 dict 넷으로 흩어져 있다(`thresholds`·`neighbor_counts`·`min_member_counts`·`weld_axes`).
꺼낼 때마다 `threshold_of`·`neighbors_of`·`members_of`·`welds_of` 를 따로 부르고, 손잡이를 더할 때마다
dict 가 하나씩 는다.

```python
Axis(coords, k, neighbors, min_members, weld=True, impute=True)
cluster(axes: list[Axis], join=...)
```

- **정책은 포맷이 안 든다.** `outline` 이 늘 primary 인 게 아니고(물음이 바뀌면 뒤집힌다), weld 는
  특정 병합 구현의 개념이라 다른 연결 방법엔 그 손잡이가 없다. 포맷이 선언하면 **데이터모델이 분석
  맥락을 알게 된다** — 걷어내기로 한 `Claims` 와 같은 역류다.
- 포맷이 주는 것은 **측정값까지**(노이즈 바닥·채널 수·이산성). 그 값을 보고 정하는 건 호출 측.
- config → `Axis` 변환은 LENS 가 든다(레시피).

#### 폴더 — 갈리는 기준은 arity

| 연산 | 대상 | 자리 |
|---|---|---|
| 압축·변환 (접기 · `cartesian↔radial`) | 한 포맷 안에서 닫힘 | `func/format/<포맷>/` |
| 군집·종합 (`fit`·`join`·weld·`impute`) | 여러 포맷 사이 | `func/format/clustering/` |

#### ③ 정규화 — 실은 "`k` 를 무엇으로 재나"

`equalize` 는 **도메인당 스칼라** `mean`·`std` 를 쓴다(채널별이 아니다). 즉 상사변환이라 거리가 일정
배로만 바뀌고 **분할 결과는 안 바뀐다 — `k` 의 단위만 바뀐다.**

| 후보 | 좌표 | `k` 의 뜻 |
|---|---|---|
| `none` — 안 한다 | 원 단위 (px) | 채널당 평균 몇 px |
| `equalize` — 지금 | `(x−μ)/σ/√D` | 채널당 평균 몇 σ |
| `floor` — 노이즈 바닥 | `x / floor(축)` | 바닥의 몇 배 |

- `none` 의 값어치: `radial_rle` 계열은 채널이 전부 px 라 원 단위가 이미 물리적 뜻을 갖는다. σ 로
  나누면 데이터 의존 상수가 끼어들어 **표본 구성이 바뀌면 같은 `k` 가 다른 뜻**이 된다.
- `floor` 의 계기: 축을 건너 `k` 의 뜻이 안 맞는다 — 실측 `outline` `k=0.05` 는 type 중심 최근접거리
  중앙값의 0.71배인데 `signed` 는 같은 값이 0.85배다. 바닥의 조작적 정의는 미정.
- **기하가 바뀌는 갈래는 따로** — 채널별 백색화·PCA·거리함수 교체는 같은 목록에 안 섞는다.
- `impute_bound` 도 σ 절대값이라 같은 문제를 갖는다(③이 서면 해소).

#### 축 연결 — 곱집합은 격자의 한쪽 끝

| 후보 | 규칙 | 성향 |
|---|---|---|
| **곱집합** (지금) | 모든 축이 "같다" 해야 같다 | 가장 잘게 — 한 축의 가름이 늘 이긴다 |
| 합집합 | 한 축이라도 "같다" 하면 같다 (전이 폐포) | 가장 굵게 |
| k-of-n 다수결 | n 축 중 m 개가 "같다" 하면 | 사이 · **축 3개 이상**에서만 뜻이 있다 |
| 공발생(co-association) | "같은 type 에 든 축 수 ÷ 축 수" 로 다시 군집 | 사이 · 축 2개에서도 된다 |
| 좌표 이어붙이기 | 축을 안 나누고 한 번에 가른다 | 축 개념 자체가 없다 |

마지막 것은 config 주석이 왜 안 하는지 적어 뒀는데(정규화 상수 공유 · 노이즈 바닥 다름 · 단위 교환
불가) ③이 서면 앞의 둘이 약해지므로 **다시 볼 값어치가 생긴다.**

`impute`·weld 는 연결 **방법**이 아니라 그 위의 **손잡이**다 — 어느 방법을 골라도 따로 켜고 끌 수
있어야 하는데 지금 곱집합에 붙어 있어 분리가 안 된다.

#### 먼저 정할 것

- 축 연결 후보가 `k`·중심을 전제하는 화면(해상도 슬라이더 · weld · 근접 그래프)과 어디까지 호환돼야
  하나. 좌표 이어붙이기는 축별 화면이 없어지고, 보류(`POOL`) 개념이 없는 방법도 있다.
- **`index` 를 어디서 가르나** — `Cluster_Bucket` 이 밖으로 가면 한 dict 에 든 둘이 갈려야 한다:
  `sign`·`types`·`dists`(군집 산출, 밖) ↔ `class`·`state`(라벨·검수, LENS).

## 논의 대상

### 화면

- **두 축의 교차표를 세울지** — 종합 트리 갈래 이름이 `#12 [outline 3 · signed 7]` 이라 옆 갈래와
  대조하면 읽히긴 한다. 진짜 교차표(행 × 열)가 더 필요한지는 써 보고 정한다.
- **`type` 안에서 쌍별 1-NN** — "여러 class" 를 그대로 "안 갈림" 으로 읽으면 안 된다. 작은 class 가
  큰 class 안에 들어앉은 형태는 한 type 에 오는데 국소로는 갈린다(실측 `c151+c153` 85% · `c150+c152` 97%).
  저장된 feature 만으로 가능하다.
- **`min_members` 기본값** — 3(옛 암묵값)으로 돌렸다. 승격 문턱이라 화면에서 만져 본다.
- **출력 문구** — 모든 판정은 *이 데이터에 대한 진술*이다. "c100 = c102" 가 아니라 "이 feature 로
  안 갈림". 화면·리포트에 박을 자리.

### config·배선

- **config 구성이 직관적이지 않다 — 전면 재정리.** `modules:`(torch 등록 보일러플레이트)와 `gauges:`
  가 한 파일에 같은 깊이로 있어 **어느 쪽을 고치면 재추출인지**가 안 읽힌다. `radial_domains: [rle]`
  도 이름만 남은 흔적이다.
  **정할 것**: 파일을 가를지(사슬 ↔ 잣대) · 등록 보일러플레이트를 걷을지 · 키 이름을 수명(재추출
  필요/불필요)이 드러나게 지을지.
- **`inject` → `process.Stage` 병합.** 걸림돌: `Stage` 는 체인 엔진인데 추출은 한 걸음, 신선도
  게이트가 순회 훅에 필요, `OUTPUTS` 가 ClassVar 인데 도메인은 config 종속.
  **정할 것**: `Stage` 가 빌드 시점에 인스턴스에게 물어보게 열 수 있나.
- **feature 를 정본 트리에.** 지금 별도 store(`.analysis/`). 정본 leaf 로 옮기면 Restore 3.4→3.8s ·
  사이드카 8.2→11.6MB. 옛 재검토 조건("여러 config 를 나란히 비교하나")은 없어졌다.
  남은 물음은 수명뿐 — 정본에 넣으면 `[feature 삭제]` 가 폴더 하나 지우기로 안 끝난다.
