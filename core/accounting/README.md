# Core Accounting Module

## 개요
이 모듈(`core/accounting`)은 CACHE 프로젝트의 핵심 비즈니스 로직을 담당합니다. 데이터베이스 모델링과 API 사이에서 데이터의 무결성을 보장하고, 복식부기 원칙에 따른 트랜잭션 처리 기능을 제공합니다.

상세한 회계 규칙과 정의는 [Accounting Rules 문서](../../docs/accounting_rules.md)를 참고하십시오.

## 모듈 구성 요소

### 1. 데이터 구조 및 타입 (`typing.py`, `models.py`)
*   **Account Types:** 자산, 부채, 자본, 수익, 비용 등 계정 과목의 열거형(Enum) 정의.
*   **Models:** `Account`(계정), `Transaction`(거래), `JournalEntry`(분개) 등 데이터 전송 객체(DTO) 및 DB 모델 정의.
*   **Rules:** 거래의 8요소 및 계정 타입별 차/대변 로직은 `typing.py`의 정의와 `docs/accounting_rules.md`의 규칙을 따릅니다.

### 2. General Ledger (`ledger.py`)
회계 원장을 관리하는 컨트롤러입니다.
*   **트랜잭션 기록:** 모든 거래 내역(Journal Entry)의 생성 및 저장.
*   **대차평형 검증 (Validation):** 트랜잭션 저장 전 `차변 합계 == 대변 합계` 여부 확인.
*   **무결성 보장:** 필수 데이터(날짜, 적요, 금액 등) 누락 여부 확인.
*   **JSON 내보내기:** 백업 및 분석을 위한 데이터 추출 기능.

### 3. Reporting Engine (Planned)
*   *추후 구현 예정 (`report.py`)*
*   재무상태표 (Balance Sheet) 및 손익계산서 (Income Statement) 산출.

## Advanced Usage (복합 거래 구현 가이드)

### 1. 주식/투자 계좌 (Investment)
주식이나 코인 등 변동성이 있는 자산은 **'취득 원가'**와 **'평가/실현 손익'** 관리가 필요합니다.

*   **계정 설정:**
    *   `1200 주식(자산)`
    *   `4200 투자수익(수익)` / `5200 투자손실(비용)`
    *   *선택사항:* `3200 평가손익(자본조정/미실현)` - 가계부 레벨에서는 실현 손익만 관리하는 것을 권장.

*   **거래 패턴:**
    1.  **매수 (취득):** 수수료 포함 총 비용을 자산으로 잡습니다.
        *   (차) 주식 1,000,000 / (대) 예수금 1,000,000
    2.  **매도 (이익 실현):** 취득 원가만큼 자산을 감소시키고, 차액을 수익으로 잡습니다.
        *   (차) 예수금 1,200,000 / (대) 주식 1,000,000
                                / (대) 투자수익 200,000
    3.  **매도 (손실 실현):**
        *   (차) 예수금 800,000  / (대) 주식 1,000,000
        *   (차) 투자손실 200,000

### 2. 신용카드 할부 (Installments)
할부는 **'발생주의(Accrual Basis)'** 원칙에 따라 물건을 산 시점에 부채 전액을 인식해야 정확한 자산 상태를 알 수 있습니다.

*   **계정 설정:**
    *   `2100 미지급금(부채)` - 카드사별로 관리하거나 통합 관리.

*   **거래 패턴:**
    1.  **할부 결제 시점 (100만원, 10개월 할부):**
        *   돈은 아직 안 나갔지만, 빚은 확정되었습니다.
        *   (차) 비품(노트북) 1,000,000 / (대) 미지급금(OO카드) 1,000,000
    2.  **매월 카드 대금 납부 시 (1회차):**
        *   부채를 나누어 갚습니다.
        *   (차) 미지급금 100,000 / (대) 보통예금 100,000
    
    > **Tip:** UI/UX 레벨에서는 "이번 달 나갈 돈(예정)"을 보여주기 위해, 트랜잭션 메타데이터에 `installment: { current: 1, total: 10 }` 정보를 저장해두고 별도 로직으로 계산하는 것이 좋습니다.

## 모듈 간 의존성
이 모듈은 `core/assets`(증빙 자료) 및 `core/geo`(위치 정보) 모듈과 연동될 수 있으나, 회계 로직 자체는 독립적으로 동작할 수 있도록 설계되어야 합니다.
